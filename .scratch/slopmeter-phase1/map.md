# Slopmeter Phase 1 — map

Label: wayfinder:map
Spec: [Clean Software Enforcement Tool — Design Spec](https://claude.ai/artifact/9KjxgFjszCmYaC8nWhPprJ)
Charted: 2026-10-26

## Destination

A Phase 1 MVP of **slopmeter** that an agent loop can be gated on: a Rust binary that scores Python, Rust and C++ source against the function-scope rules (F01–F12, F15), with F07, F09, F10 and F12 warns and the rest gates, plus a coverage gate on changed lines, reads coverage for CRAP, emits the JSON report and the worst-first text table with exit codes, supports `--changed` and `explain`, and is installable with `cargo install` from this repo. Shipped means: the gates are set by a stated, reproducible method and flag real slop in the clean repos' worst functions; the diff scoping and the adapters have no whole-body blind spots the review found; the sloppy corpora fail by a wide margin at those gates; and the self-check runs in CI.

Redrawn 2026-10-27 after [the Phase 1 review](../../docs/review/2026-10-27-phase1-review.md): the first destination (validation run passes) was reached on 2026-10-27, but the gates it produced flag nothing, so the effort continues under this one. The mutation-testing decision is in scope; its per-language readers are fog until it is made.

## Notes

- **Execution is in scope.** This map carries building, not only deciding (overrides the wayfinder plan-don't-do default). Decision tickets come first; build slices graduate from the fog once the IR, report and config are frozen.
- **Standing decisions from charting:** name is `slopmeter` (binary, config file `slopmeter.toml`, cache dir, crate); core language is Rust (see `docs/adr/0001-rust-core.md`); adapters are built in the order Python → Rust → C++, and the IR freezes after the Python adapter proves it on real repos. TypeScript, which the spec put first, is deferred (Out of scope).
- **Skills to consult:** `/grilling` and `/domain-modeling` for decision tickets (glossary lives in `CONTEXT.md`); `/prototype` and `/design-an-interface` for prototype tickets; `/research` for research tickets; `/writing-plans` when build slices graduate.
- **Tracker:** local markdown in this directory, including after the GitHub repo exists. The decisions stay files in git. See [Repo, crate layout, CI and where the GitHub repo lives](issues/18-repo-layout.md).
- **Spec gaps found while charting:** the spec's JSON report schema and escalation example code blocks are empty in the doc. The report schema is therefore a prototype ticket, not a given.
- **Review of the first build (2026-10-27):** [the Phase 1 review](../../docs/review/2026-10-27-phase1-review.md) ranks what the build got wrong; tickets 46–66 chart its next steps. Its raw artifacts (per-function distributions over the nine corpus repos, adversarial fixtures per language) were left in the review session's scratchpad and are quoted in the tickets that need them.
- **Gap review (2026-10-29):** with every destination item shipped, the map was checked against the spec's catalog and the gate an agent loop can dodge. Tickets 79–84 chart it: a waiver the change itself writes and a stale report both pass today, the CI self-check never gates coverage or mutation, and the spec's F09, F10, F12 and F15 were never placed on the map.
- **Spec terms the tool keeps:** the rule IDs (F01…), tiers (A/B/C), gate vs warn, `slop_score` per KLOC, `fix_shape`, `anti_fix`, `principle`, `scope: changed` with `inherited` findings, the six-stage pipeline (inputs → adapters → IR → analyzers → rule engine → reporters).

## Decisions so far

<!-- one line per closed ticket: gist, then the link for the detail -->
- [tree-sitter grammars for Python, Rust and C++ from Rust](issues/01-tree-sitter-grammars.md) — `tree-sitter` 0.27.1 with the org's python 0.25.0 / rust 0.24.2 crates; crates.io cpp 0.23.4 has no modules, so the language-surface decision pins master instead; Rust macro bodies are opaque and C++ `#if`/macros split statements and leak into `&&`/`||` counts, so [C++ preprocessor and template handling](issues/16-cpp-preprocessor.md) has its facts.
- [How radon, rust-code-analysis and lizard count cyclomatic complexity](issues/04-cross-check-tools.md) — all agree on base 1 + if/loop/catch/ternary/&&/||; they split on `with`, `assert`, `finally`, Python `match`, Rust match arms (+3 vs +2), C++ `default` and `#if`, so ticket 07 must pick per-language parity targets or a bounded delta.
- [SonarSource cognitive complexity rules mapped to Python, Rust, C++](issues/03-cognitive-complexity.md) — implement from white paper v1.7 Appendix B; sonar-python and the official sonar-rust give per-construct tables; clippy's lint is a different metric; C++ reference is the community sonar-cxx; recursion is unimplemented everywhere and `match` handling differs per language.
- [Coverage formats: coverage.py LCOV, cargo-llvm-cov, gcov/lcov](issues/02-coverage-formats.md) — no tool gives a per-function coverage fraction via FN/FNDA, so derive it from DA line hits intersected with the IR function's line range; never key on FN names (three naming schemes, two mangled); parse both legacy FN/FNDA and lcov 2.2's FNL/FNA.
- [Install the Rust toolchain on this machine](issues/05-install-rust-toolchain.md) — stable rustc/cargo 1.99.1 (`aarch64-apple-darwin`) via rustup 1.29.2, plus rustfmt, clippy, llvm-tools-preview (LLVM 23.1.1) and cargo-llvm-cov 0.9.1; `~/.cargo/bin` is on PATH through `~/.zshenv`.
- [What counts as a function, per language](issues/06-what-is-a-function.md) — a named definition with a written body; a lambda inside a function folds into it, and a lambda bound to a name outside any function is itself a function; identity is the file of the body plus the qualified name, with C++ parameter types for overloads ([ADR 0002](../../docs/adr/0002-what-counts-as-a-function.md)).
- [Cyclomatic complexity counting rules, per language](issues/07-cc-counting-rules.md) — own rules: base 1, +1 per decision point; a residual arm, a jump, and syntax that does not choose a path add nothing; the cross-check tools may differ by a listed delta ([ADR 0003](../../docs/adr/0003-cyclomatic-complexity-rules.md)).
- [File extensions, dialects and headers per language](issues/08-language-surface.md) — claim `.py`, `.rs`, and the C++ source, header, inline, and module extensions (`.cppm`, `.ixx`); parse each file once and do not follow `#include`; promise Python 3.9+, Rust as the pinned grammar parses it, and C++17 plus C++20 modules via tree-sitter-cpp `c009222` ([ADR 0004](../../docs/adr/0004-tree-sitter-cpp-master-pin.md)).
- [Source selection and test-file policy](issues/09-source-selection.md) — every claimed file in the repo, minus gitignore, build and vendor directories, protobuf names, and tests; tests return only through a switch; `build.rs`, `examples/`, and `benches/` stay in ([ADR 0005](../../docs/adr/0005-scored-set.md)).
- [Gate on the max finding or on slop_score](issues/10-gate-max-vs-aggregate.md) — the run fails on a Tier A finding over its gate level, not on `slop_score`; the score is reported and has no ceiling in Phase 1; a lower level on the same rule is a warn ([ADR 0006](../../docs/adr/0006-gate-on-the-finding.md)).
- [Diff-scoped by default, inherited findings, and --strict](issues/11-diff-scoped-default.md) — default run gates only touched functions; a touched function still over its gate level fails even if the value improved; untouched findings are inherited and do not gate; an empty diff gates nothing; `--strict` scores the whole repo ([ADR 0007](../../docs/adr/0007-diff-scoped-default.md)).
- [What --changed means](issues/12-changed-semantics.md) — the diff is the merge-base with `main` through the working tree, or `master` if `main` is missing; a function is touched when a changed line hits its span, including decorators and attributes; no base ref fails the run; outside git the whole scored set is scored ([ADR 0008](../../docs/adr/0008-what-changed-means.md)).
- [Pass-through and Demeter detection without symbol resolution](issues/13-passthrough-demeter-exemptions.md) — F07 is a syntactic pass-through at 80% or more of the ordinary parameters and warns; F08 gates a member chain over two hops from the receiver or one hop otherwise, with a per-language allow-list and a trailing `build` run ignored; the two-implementation exemption is dropped ([ADR 0009](../../docs/adr/0009-passthrough-warns-chain-gates.md)).
- [What a Phase 1 finding carries](issues/14-finding-payload.md) — one finding per rule per function, at the worst site; it carries the level it is over (`gate` or `warn`), a fix shape filled with the measured value and that threshold, and one anti-fix sentence; it does not predict the edit ([ADR 0010](../../docs/adr/0010-finding-payload.md)).
- [Attributing coverage records to IR functions, per language](issues/15-coverage-attribution.md) — CRAP reads hit `DA` lines over `DA` lines in the function's range; names are ignored; a missing report is absent coverage, not 0%; the tool reads a report and does not run the tests ([ADR 0011](../../docs/adr/0011-coverage-by-line-range.md)).
- [C++ preprocessor and template handling](issues/16-cpp-preprocessor.md) — C++ is parsed as text, with no preprocessor and no `compile_commands.json`; every `#if` arm counts except a literal `0`; macro bodies are unscored; a partial parse is scored and `unparsed_ratio` does not fail the run ([ADR 0012](../../docs/adr/0012-cpp-scored-as-text.md)).
- [Validation corpus per language](issues/17-validation-corpus.md) — `--strict` on three pinned repos per language until they have no gate findings; the sloppy repo is an agent-written tree, pinned once it gates on every gating rule and warns on F07 ([ADR 0013](../../docs/adr/0013-validation-corpus.md)).
- [Repo, crate layout, CI and where the GitHub repo lives](issues/18-repo-layout.md) — one crate, `slopmeter`, grammars as dependencies; a public personal GitHub repo with the markdown tracker kept; research notes on `main`; CI is fmt, clippy, and tests until thresholds exist ([ADR 0014](../../docs/adr/0014-one-crate-public-repo.md)).
- [Freeze the Phase 1 IR schema](issues/19-ir-schema.md) — scored files and their functions, in memory, with no version field; the adapter records line spans, parameters, decision lines, chain hops, and a forwarding call; classes, edges, churn, and coverage stay out ([ADR 0015](../../docs/adr/0015-ir-is-files-and-functions.md)).
- [The adapter interface contract](issues/20-adapter-contract.md) — one `parse(path, source) -> File` per language, once per selected file; the module also publishes that language's default allow-list; a new language adds a `Language` variant and one extension arm ([ADR 0016](../../docs/adr/0016-adapter-parses-one-file.md)).
- [Define the JSON report schema](issues/21-report-schema.md) — `findings` are touched functions and `inherited` are the rest; the verdict fails only on a gate in `findings`; the score sums both lists over physical KLOC and does not fail the run ([ADR 0017](../../docs/adr/0017-json-report-lists-what-must-be-cleared.md)).
- [Shape of slopmeter.toml](issues/22-config-shape.md) — the file records departures from the built-in profiles: a coverage path, include and exclude patterns, a `warn` or a `gate`, and allow-list names; a missing file is the built-in; an unknown key fails the run ([ADR 0018](../../docs/adr/0018-config-records-departures.md)).
- [Text table and explain output format](issues/23-text-and-explain-output.md) — the table is the check a person reads and `--json` prints the report instead; a finished check exits 0 or 1, and no check exits 2; `explain` is one page on the shipped threshold ([ADR 0019](../../docs/adr/0019-text-table-and-explain.md)).
- [Cognitive complexity increments](issues/24-cognitive-complexity-increments.md) — F03 uses the white paper's table in all three languages; recursion, nested-function depth, and `#if` add nothing; a nested break costs 1 plus its depth ([ADR 0020](../../docs/adr/0020-cognitive-complexity-increments.md)).
- [What increments a logical line](issues/25-lloc-counting.md) — `lloc` is the number of statements in the body; a blank, a comment, a docstring, a brace, and an attribute add nothing; a closure's statements count on the enclosing function ([ADR 0021](../../docs/adr/0021-logical-line-is-a-statement.md)).
- [Plan the Phase 1 build](issues/26-plan-the-build.md) — sixteen session-sized slices, crate and IR first and the C++ validation run last; F01, F02, F04, F05, F06, and F11 still need a metric before the rule engine ([the plan](../../docs/superpowers/plans/2026-10-27-phase1.md)).

- [Score Rust macro token trees](issues/67-rust-macro-tokens.md) — `adapters::rust` scores an invocation on the enclosing function, scores a `macro_rules!` body where it is written, and treats an `fn` inside a macro as its own function ([ADR 0024](../../docs/adr/0024-rust-macro-tokens.md)).

- [Report unparsed_ratio per file and compute it from leaf error spans](issues/52-unparsed-ratio-report.md) — a file above ratio 0 is noted and does not fail the run; the ratio counts lines whose tokens sit under an error, so fmt `format.h` is 0.069 instead of 0.993 and the split-`#if` fixture stays at 0.25 ([ADR 0012](../../docs/adr/0012-cpp-scored-as-text.md)).

- [How C++ function-like macros are surfaced or expanded](issues/55-cpp-macro-policy.md) — a file notes how many function-like `#define`s have unscored bodies, and the note does not fail the run; a C++ mutation gate may read a report and does not read `compile_commands.json` ([ADR 0012](../../docs/adr/0012-cpp-scored-as-text.md)).
- [Note unscored C++ function-like macros](issues/68-cpp-macro-note.md) — `File::unscored_macros` counts function-like `#define`s outside a literal-`0` arm, and a count above 0 is a note that does not fail the run ([ADR 0012](../../docs/adr/0012-cpp-scored-as-text.md)).
- [Count Rust expression-position bodies and nesting per the ADRs](issues/56-rust-lloc-and-nesting.md) — an `if`, a `match`, or a closure expression body adds a logical line only in statement position. Nesting is [Whether nesting is the deepest decision or the deepest structure](issues/69-what-nesting-counts.md).
- [Align the Python adapter with ADR 0003 and 0009](issues/57-python-adapter-alignment.md) — a bare call is a hop only when it is the whole chain; a loop or `try` `else` adds no decision and is a radon delta; a lambda in a default or decorator counts on that function; a waiver comment has to occupy its line alone.
- [What a pass-through is when one extra statement dodges it](issues/58-passthrough-tightening.md) — a logging statement and a dead assignment may sit beside the one call; `Ok`, `Some`, and `Err` peel; the call's object counts; a non-literal extra argument disqualifies the call; a pack expansion forwards the pack ([ADR 0009](../../docs/adr/0009-passthrough-warns-chain-gates.md)).
- [Fix the LCOV join edge cases](issues/59-lcov-edge-cases.md) — a second record that matches the same file is a tie and leaves coverage absent; an empty `DA` checksum is a listed line; a missing report path is named in the note ([ADR 0011](../../docs/adr/0011-coverage-by-line-range.md)).
- [A coverage gate on changed lines](issues/60-coverage-gate.md) — S06 gates the hit `DA` fraction of a touched function at 100%; a missing report fails that run; `--strict` keeps shown rows inherited; a waiver line for S06 fails the run ([ADR 0026](../../docs/adr/0026-coverage-gate-on-a-changed-function.md)).
- [Mutation testing as a slopmeter gate](issues/61-mutation-testing.md) — S07 gates the mutation score of a touched function at 1; the tool reads a report and does not run the mutator; a missing report fails that run; `--strict` keeps shown rows inherited; a waiver line for S07 fails the run ([ADR 0027](../../docs/adr/0027-mutation-score-on-a-changed-function.md)).
- [Which gates the config may move, and how the report shows it](issues/62-config-overrides.md) — a count gate may rise to twice that language's built-in, F03's warn tops out at 20, and each departure is a run-level note ([ADR 0028](../../docs/adr/0028-count-gate-twice-the-built-in.md)).
- [Reconcile rule ids with the spec and the dropped commented-out-code rule](issues/63-rule-numbering.md) — the tool keeps its ids: F04 parameters, F05 nesting, F06 physical length, F11 logical lines; commented-out code is out of scope ([ADR 0029](../../docs/adr/0029-shipped-rule-ids-stand.md)).
- [Whether nesting is the deepest decision or the deepest structure](issues/69-what-nesting-counts.md) — nesting is the deepest structural level: an `if`, a loop, a `match` or `switch`, a ternary, and a `catch` each add one, and a boolean, a lambda, an `else` chain, a guard, a comprehension, a `try`, a `with`, and a `#if` add none ([ADR 0030](../../docs/adr/0030-nesting-is-structural.md)).
- [Drop a C++ bare call that only starts a member chain](issues/70-cpp-bare-call-chain.md) — `make().a.b.c`, `(make()).a.b`, and `make()->a.b` are the members after the call; `send()` stays one hop.
- [Read a cargo-mutants report into S07](issues/71-cargo-mutants-report.md) — `score_rust` reads `outcomes.json`; caught and timeout are detected, missed is undetected, and unviable is left out; S07 gates at 1, a missing report fails a touched Rust function, and a waiver for S07 fails the run.
- [Read a mutmut store into S07](issues/72-mutmut-store.md) — `score_python` reads `mutants/<file>.meta`; killed and timeout are detected, survived and no-tests are undetected, and a type-check rejection is left out; the start line comes from the orig copy, and an unfinished mutant fails the file.
- [Read a mull report into S07](issues/73-mull-report.md) — `score_cpp` reads mull's mutation-testing-elements JSON; killed and timeout are detected, survived and no coverage are undetected, and a compile error or a runtime error is left out; a pending or ignored mutant fails the file.
- [Accept a bounded count gate and note the departure](issues/74-bounded-gate-overrides.md) — a count gate may be 0 through twice that language's built-in, F03's warn tops out at 20 and its gate floor is 1, and each departure is a run-level note that does not fail the run.
- [Count nesting as the deepest structural level](issues/75-structural-nesting.md) — an `if`, a loop, a `match` or `switch`, a ternary, and a `catch` each add one, and the finding sits on the deepest of those lines.
- [Recalibrate the gates by percentile on a production-only set](issues/46-recalibrate-gates.md) — each count gate is the nearest-rank percentile of that language's three pinned commits, measured 2026-10-29, and a later measurement may replace the integers; a clean-repo function over the gate fails ([ADR 0031](../../docs/adr/0031-count-gates-are-a-percentile.md)).
- [Fix the explain pages and the CLI surface](issues/64-explain-and-cli-polish.md) — each explain page's threshold is one table and names no stand-in; F02's after adds a test; `--help` and `--version` print and exit 0; `--changed` with `--strict`, and `--changed` outside git, are usage errors; a waiver that names no rule is the finding `waiver`.
- [Rewrite the sloppy corpora so they are sloppy, not gate plus one](issues/66-rewrite-sloppy-corpus.md) — each tree was written again from its seed; the worst measurement on every gating rule is at least one and a half times that threshold and more than one past it, the pass-through is 100, and `hold` is unhit in the coverage report.
- [Whether a run scores every claimed extension](issues/76-secondary-language-files.md) — a run scores every claimed extension under that file's profile; a profile's percentile is the files of that language in its three pins, and `exclude` is how a project narrows the languages.
- [Whether the self-check joins CI while the crate is over its gates](issues/77-self-check-over-gates.md) — the self-check stays off CI until `slopmeter --strict` on this repo exits 0; bringing the crate under the gates stays in this destination, and there is no baseline of the 364 findings.
- [Bring this crate under the gates](issues/78-under-the-gates.md) — `slopmeter --strict` on this repo exits 0, with the thresholds and `slopmeter.toml` left as they were.
- [Put the self-check in CI and create the GitHub remote](issues/65-self-check-and-remote.md) — the public repo is https://github.com/crussell187/slopmeter, with the four research branches already there; the CI job runs `cargo run --quiet -- --strict` after the tests.
- [Waivers under an agent loop](issues/79-waivers-under-an-agent-loop.md) — a waiver line the diff adds does not hold on that run; unchanged lines, `--strict` and a run outside git hold every well-formed waiver; no switch refuses waivers and the number has no cap; the report counts held waivers as `waived` ([ADR 0034](../../docs/adr/0034-a-waiver-the-change-adds-does-not-hold.md)).
- [Whether a stale coverage or mutation report holds](issues/80-stale-reports.md) — a report older than any file the diff changed is missing: touched functions fail S06 and S07 and CRAP is absent; under `--strict` the comparison is per scored file and adds a note, not a row; freshness is modification time and a tie is fresh ([ADR 0035](../../docs/adr/0035-a-report-older-than-the-change-is-missing.md)).
- [Place F09, F10 and F12 on the map](issues/82-place-f09-f10-f12.md) — weight-1 warns, each only where it applies: F09 inline I/O in all three languages with a config `allow`, F10 void-mutates-argument in Python and C++, F12 null literal in C++ only; no gate level, no switch, a waiver for them fails the run ([ADR 0036](../../docs/adr/0036-three-warns-where-they-apply.md)).
- [Whether an empty or swallowing catch ships as F15](issues/83-empty-catch-rule.md) — a weight-10 gate in all three languages on a handler whose body does nothing; an assignment, a call, a return, a re-raise or a `?` is handling; no config key, ordinary waiver ([ADR 0037](../../docs/adr/0037-a-swallowing-handler-is-a-gate.md)).
- [Run coverage and mutation in CI and gate the pull request's touched functions](issues/81-ci-coverage-and-mutation.md) — a pull request pins cargo-llvm-cov 0.9.1 and cargo-mutants 27.1.0, then `slopmeter --changed origin/main` fails the job; a push to `main` keeps `--strict` only; this crate lists 4117 mutants and the 20 in `src/explain.rs` took 78 seconds.
- [Score an empty or swallowing catch](issues/84-score-empty-catch.md) — each adapter records the line of a handler that does nothing, and `rules::evaluate` emits one weight-10 gate at the first such line.
- [Reject a waiver the change adds and count the held ones](issues/85-reject-added-waivers.md) — a waiver line in the diff's added set does not hold, the row says it was written by this change, and the report counts the waivers that hold.
- [Treat a report older than the change as missing](issues/86-stale-report-check.md) — a report older than any path the diff changed is missing: touched functions fail S06 or S07, CRAP is absent, and one note names the newest path; under `--strict` and outside git a newer scored file the report matches gets the note and no row; mutmut uses each `.meta` time and the newest `.meta` against the diff; a tie is fresh.
- [Score an inline I/O dependency as F09](issues/87-score-f09.md) — a call whose written name is on the language list is one weight-1 warn at the first such call; `[F09] allow` names the calls that do not count, and each name is a departure note.

## Not yet specified
