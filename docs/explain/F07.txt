F07  pass-through

A function that only hands its parameters to one call adds a hop and
no behavior. It warns, and it does not fail the run.

Counting
The body hands ordinary parameters to one call. A logging
statement and an assignment to a name that is never read may
sit beside that call. The call may be wrapped in Ok, Some, or
Err, and it may be returned or awaited. A parameter counts when
it is an argument, the call's object, or a pack expansion of
that hand-off. A literal argument does not change the ratio.
Any other argument means the function is not a pass-through.
The ratio is how many ordinary parameters are handed on
unchanged, over how many ordinary parameters there are. The
receiver is in neither count. The finding is that ratio, at the
call, when it is at least 80 percent. There is no gate level.

Threshold
        warn
Python    80
Rust      80
C++       80
The warn is 80 percent of ordinary parameters. No gate.
A waiver line for F07 fails the run, because F07 is not a gate.

Before
def city(response):
    return response.get("city")

After
def city(response):
    name = response.get("city")
    return name.strip()

Anti-fixes
Renaming the forwarded parameters leaves the ratio in place.
Awaiting the same call, or returning it, is still one forward.
A docstring above the call does not change the ratio.
A logging statement beside the call does not change the ratio.
