# LCOV and CRAP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Join an LCOV report to each function's body span, compute CRAP, and leave CRAP unset when coverage is absent.

**Architecture:** `inputs::read_lcov` reads `SF` and `DA` records and ignores function records. `inputs::cover` joins those lines to the scored paths and writes `Measurement::crap`. It does not evaluate rules or render. The binary stays empty until a later session wires the pipeline. `--coverage` already replaces the file key on `Config`; this session reads whichever path that leaves.

**Tech Stack:** Rust stable, edition 2021. No new dependencies.

## Global Constraints

- Coverage is hit `DA` lines over `DA` lines in the body span. A count above zero is a hit. `FN`, `FNDA`, `FNL`, and `FNA` are ignored. The reader still accepts a file that contains them.
- An `SF` path matches a scored file when the repo-relative path is a directory-boundary suffix of it, after `\` becomes `/` and `.` and `..` resolve lexically. The longer scored path wins. Several sections that land on one scored file merge: a line is listed if any section lists it, and it is a hit if any count is above zero. A tie leaves that file's coverage absent and the run notes it.
- A nested function's lines come out of the parent. A lambda or closure stays with the function that contains it. A header is covered only by its own record.
- `DA` lines all at zero are coverage 0, and CRAP runs. No listed lines in the span leaves CRAP unset. CRAP is CC squared times the uncovered fraction cubed, plus CC. Coverage is a fraction from 0 to 1.
- No report, or a path that is not a file, is one run-level note: `No coverage report was given. CRAP was not computed.` A scored file with no matching record is `No coverage record matches this file.` A tie is `Coverage records tie for this file.` A function with no `DA` lines is `<name> has no DA lines.` None of these notes gate.
- A bad `SF` or `DA` record fails the read: `coverage report <path>:<line> has a bad record`.
- The file key is repo-relative and is read from the root. `--coverage` replaces it and may be absolute.

```rust
pub struct Section {
    pub path: String,
    pub lines: BTreeMap<u32, bool>,
}

    pub sections: Vec<Section>,
}

    Read(PathBuf, std::io::Error),
    BadRecord { path: PathBuf, line: usize },
}

pub fn read_lcov(path: &Path) -> Result<Coverage, LcovError>

pub fn coverage_path(root: &Path, coverage: Option<&str>) -> Option<PathBuf>

pub fn cover(
    measurements: &mut [Measurement],
    scored: &[&str],
    report: Option<&Path>,
) -> Result<Vec<Note>, LcovError>
```
